How it's built

One small server owns the game. An automation platform runs every turn. Two AI agents make the decisions. A Chainlink oracle brings in the real ETH price, and a smart contract keeps a public, tamper-proof record. Every piece runs on free tiers or a test network.

Architecture

The Generals: AI agents

Each turn the general gets its personality, a rules summary, its journal (memory) and past-season lessons. It calls read-only tools (get_battlefield, get_enemy_position, get_market) and then exactly one order tool. The server dry-runs every order through the same rules engine the game uses; an illegal order goes back to the model with the reason, and it corrects itself. The model never touches the game state directly.

Limits per decision: 5 model calls, 45 seconds, a daily call cap below the free quota. If the AI is unavailable, a rule-based bot takes over and the page says so ("standing orders"). Spectators can't send any text, so nothing typed by the public ever reaches a prompt.

The Automations: n8n

Turn Router (event-driven orchestration). Built only from standard nodes:

  1. Webhook receives "new turn" from the world and replies at once.
  2. HTTP Request reads the kingdom's gold and food.
  3. IF food is below 20%, then HTTP Request reorders food automatically (threshold alert → reorder).
  4. HTTP Request asks the AI general for an order (60-second timeout).
  5. HTTP Request delivers the order to the game.

Market Sync (scheduled data sync): every 10 minutes it calls the Chainlink feed with a raw JSON-RPC eth_call and posts the result to the world, which logs it whenever Chainlink has published a new price.

If n8n is down, the world notices, runs the turn itself, and logs that it did. The n8n editor is bound to localhost and never exposed publicly.

The Oracle and the Ledger: Chainlink + blockchain

The RealmLedger contract reads Chainlink's ETH/USD feed itself on every capture and stamps that price into the permanent record, alongside a hash of the full battle record. Only the game's operator wallet can write; anyone can read.

Receipts go through an outbox: one sender, strict order, retries with backoff. If the chain is unreachable, the game keeps going and the receipts are sent when it comes back.
